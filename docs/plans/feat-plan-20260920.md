# QMT 交易日历与主力、连续合约映射接入

## 目标与边界

2026-09-20 用户确认实施，采用“当前映射先可用”：接入当前主力查询及采集快照，同时尝试真实历史映射和交易所日历。不可用能力明确报告，不补造历史、不借用Tushare数据。复用既有期货资料、任务、数据库、核验、维护与导出，不扩展其他资料或拼接连续分钟。

## 接口与数据

- 纯行情桥新增当前主力、独立交易日历、历史主力的定向白名单，保持Python3.6兼容；仅使用现有大QMT上下文，不新建MiniQMT连接。
- 当前主力使用get_main_contract，不按名称、成交量或持仓猜测。历史主力尝试historymaincontract。能力区分未检测、可用、无接口、权限不足、空响应和连接失败，附检测时间和样本。
- /sources返回能力；现有/futures/options、查询、统计、同步、导出及SDK支持source=qmt；mapping_mode=current|history，Tushare旧默认不变。
- 日历复用trading_dates，增加证据与采集时间；仅完整交易所日历可确认休市，K线日期仅证明观察到开市，未知日期不补闭市，旧记录不自动升级。
- 同schema新增共享映射快照表，保存来源、连续与月份合约、采集时间、明确交易日及任务引用。缺交易日保留NULL，同任务分块幂等。历史逐日记录继续使用contract_mappings，快照不回填历史。
- 代码保留大小写和后缀，同源名称；校验跨市场、非法代码、冲突、重复、日期与截断，原始证据保留。不支持的连续指数不猜月份对应。

## 流程与页面

- 全局QMT来源开放日历、映射；其余资料保持能力限制。沿用多选、搜索、全选、快捷日期与分页。
- 日历月历/列表区分开市、休市、未知，展示依据与更新时间；映射区分当前快照和历史逐日，已存资料查询不依赖在线。
- 采集复用单源队列、取消、检查点、关联重试和事件；空表不成功，覆盖不足保留待核验。
- 新维护默认停用、17:00。日历与当前快照按自然日，重启只采一次当前快照；历史映射按已确认交易日回读最近五日。
- 行情核验和调度优先采用已确认同源日历，不将K线日期当完整日历，不改写旧行情或追溯改判任务。

## 验证与交付

- 验证白名单、旧桥、缺能力/权限/连接、空表、截断、冲突、重复、来源隔离、取消恢复与调度去重。
- 覆盖周末/节假日/未知与部分日历、终端交易日不同于采集日、快照不能填历史及缺口不连线。
- 浏览器1440/1024/768/390px流程、SDK/数据库/CSV/Parquet一致性、完整回归及构建资源检查。
- 代码测试完成后仅部署自有PFOR_MARKET；终端运行时提示用户退出，不自动关闭或覆盖其他模型。
- 实机先豆一、沪铜、股指主力，六交易所分别检测日历，历史先最近五个交易日。分别报告通过、不支持、权限不足、未验证。
