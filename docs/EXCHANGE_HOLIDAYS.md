# 交易所休市公告同步

2026-09-30 接入六家国内期货交易所官方公告。休市公告独立于 QMT、Tushare 交易日历，保存在 `exchange_notices`、`exchange_holiday_events`、`exchange_holiday_sync`，迁移版本为 14。公告不写入 `trading_dates`，不构造完整年度日历。

## 同步与使用

网页“期货资料 / 休市公告”按交易所、安排年度分页查询，支持当前版本与历史版本、原文链接、正文、发布日期、内容摘要及解析规则。原文未提供明确发布时间时保留 NULL，首次保存与最近确认时间分别保存。

同步使用独立 `exchange` 资料队列；QMT 行情接口的数据来源仍只允许 `qmt`、`tushare`。公告同步任务复用现有检查点、取消、事件和关联重试，不占用 QMT 补数队列。用户保存的维护范围按上海时间每日更新，交易所和年度固定，不自动扩展到新年度。维护计划支持启停、回收和恢复，恢复后保持停用；存在关联活动任务时拒绝删除。

发现范围为当前官方通知列表、上期所及能源中心年度页，以及此前已保存的同年度公告地址。每个交易所年度范围最多处理 40 个公告地址，发现超限会明确失败，不截断成成功；总时间 180 秒，单次读取超时 10 秒、页面上限 2MB，网络或服务器错误最多尝试三次。只接受对应官网主机的 HTTP/HTTPS 地址，重定向同样校验。访问验证、412、空白页等保留失败状态，不据此声称无公告或无交易。当前实现不承诺历史列表完整性。

## 采集判定

- 全天开休市与当晚夜盘停开、恢复分别提取；“起开市”只证明明确的恢复日，不向后扩展。未列日期保持未知，民用调休不推成交易日。
- 明确年度、日期范围和语句才能用于判定；部分品种、含糊日期、未完整识别的安排保持待核验。单纯风险管理通知仅保存原文，不提供日期结论；上期所转发能源中心公告不归入上期所安排。
- 同一地址新版本无法解析时停用旧结论，历史版本保留；访问失败则继续保留已确认的缓存。其他公告与已保存同源开市证据冲突时不自动跳过。
- QMT 历史与合约日期均空时，只有请求区间全部有明确休市证据，且本地无相反行情记录，才能标记 `not_applicable`。分钟还要求首日前一晚有明确停开或休市依据；中金所无夜盘。公告不用于猜测分钟交易日归属。
- 旧郑商所 2026 年固定公告依据保留兼容；取得当年度动态公告后，以动态证据判定，不能在动态证据未知或修订后回退旧固定结论。
- 无依据的空分块仍待核验并可定向重试，独立后续分块继续。真实认证、连接、数据库异常仍按故障处理。

## HTTP 与 SDK

`POST /exchange-holidays/sync`、`POST /exchange-holidays/query` 接受 `exchanges`（交易所数组）和 `years`（1 至 5 个年度的整数数组）。查询支持 `limit`、`offset` 和 `versions`；公告正文及版本通过 `GET /exchange-holidays/notices/{id}` 读取。

独立资料任务、维护列表分别使用 `/exchange-holidays/jobs`、`/exchange-holidays/maintenance/query`；维护保存、更新、预览、执行一次、回收和恢复复用现有维护流程。已保存公告的只读核验不请求官网，也不改写原文及历史任务。

SDK 提供 `DataClient.exchange_holidays(exchanges, years, **options)`、`DataClient.sync_exchange_holidays(exchanges, years)`。本次没有新增公告 CSV/Parquet 导出入口。
