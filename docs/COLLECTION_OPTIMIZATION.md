# 采集性能与恢复优化（2026-10-09）

本轮根据[故障诊断](collection-diagnosis-20261009.md)修正采集中的已证实问题。最终回归及正式启用记录见[验证记录](VERIFICATION.md)。所有实机时间按 Asia/Shanghai。

## 实际变更

QMT 的 MSC/MSP、-MS-C/-MS-P- 月份期权按明确代码格式识别为 option/contract。015 迁移只纠正 QMT 目录中的匹配记录，保留稳定 instrument_id、名称、终端原始资料和元数据，未改写历史行情、旧任务或期权属性。旧目录任务续跑也采用新识别，避免恢复后重新写回错误类型。

采集及只读核验按终端明确上市、到期日期处理普通合约。已确定在生命周期之外的分块记录为 not_applicable，不发送下载请求；旧错误 continuous 标签下的明确普通期权同样适用。真实连续合约仍不套用当前月份的上市日期。

每块进度、结束统计、网页详情及分页子接口采用数据库端摘要。`GET /jobs/{id}?summary=1` 和 `POST /jobs/{id}/cancel?summary=1` 保留状态、检查点、total_chunks、成员、账号及行数，省略 chunks 和 coverage。SDK `job(id, summary=True)` 可选；旧接口默认完整响应保持兼容。执行和关联重试仍读取真实范围，不截断证券或分块。

QMT 单次网络操作为首次请求加最多三次重试，等待 10/20/30 秒，每两秒检查取消、停止及工作租约；Tushare 保留 1/2/4 秒。超过边界仍保留失败和检查点，需要按既有流程创建关联重试。取消只停止后续处理，已提交终端的请求不能撤销。

暂时数据库连接故障退出当前执行，由队列重新获取租约并从持久化检查点继续；不自动重放事务。永久 SQL 错误仍保存 DATABASE_ERROR 并结束任务。驱动未提供 SQLSTATE 时，明确认证、访问限制及目标数据库不存在的错误也不进入连接创建重试。新增脱敏异常类别、SQLSTATE、连接原因及 RPC 动作，服务端终止、恢复中、超时、拒绝及连接重置可以分别定位。浏览器断开响应连接时直接关闭，避免随后误报行情源故障。

## 验证与限制

新增测试覆盖 MS 期权迁移、身份保留、旧目录及任务续跑、真实连续合约、摘要及旧 API 兼容、取消、模拟 QMT 重启恢复、数据库暂时和永久故障、脱敏及浏览器断开响应。已有 Chromium 回归覆盖桌面和移动视口；固定历史样本的日历浏览器测试使用同一固定检测时钟，避免当前月份变化导致样本被合法地判为区间外，原业务断言保持。

本次没有重启 QMT 或 PostgreSQL，也没有替换 QMT 模型。10 月 8 日 PostgreSQL 服务端终止有 SQLSTATE 和启动时间证据，其余远程间歇性超时、重启发起者仍需数据库服务器及宿主机日志。下一次真实 QMT 重启后的恢复、长期稳定性和完整约 25 万分块回补尚未实测；模拟恢复通过不能代替这些验收。终端负成交额继续拒绝入库，不取绝对值或补零。
