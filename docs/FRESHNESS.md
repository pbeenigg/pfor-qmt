# 数据新鲜度口径

「运行与日志」的新鲜度面板检查已启用的数据集自动更新及明确保存的维护计划。逐对象、周期展示，不用一个合约的新日期掩盖其他合约落后。历史归档和停用范围不参与判断。

- `current`：最新数据日期达到维护目标；不等同于历史区间连续、字段完整或分钟时段校验通过。
- `stale`：已有数据的日期落后于已确认交易日。补数前仍需核对停牌或无成交情形。
- `missing`：已确认维护目标日期，但没有该对象的对应记录。
- `pending_verification`：日历不充分、分钟时段未知，或该资料发布规则未核验。原因代码和下一步动作随行返回。
- `not_applicable`：维护区间位于上市前、到期后，或完整日历确认无开市日。
- `not_due`：尚未到达数据集启用后的首次维护时刻。
- `not_published`：周/月周期结束日尚未完整经过，保留当前计算值。
- `rejected`：周期标签或截至日等字段未通过核验。

按 Asia/Shanghai 与范围设定的维护时间计算截止日期。日线与主力映射只使用对应来源、交易所的已存日历；最近开市日之后缺少休市记录时保留待核验，不推断周末和节假日。合约资料中的上市、到期日期限制目标区间。日历资料检查截止日是否覆盖，完整历史缺日另查采集任务。

分钟展示最新原始日期，但不以自然日推断夜盘归属或宣布最新完整。周/月按已结束周期的完整日历和截至日判断；目录要求维护任务及全部分块提交证据。仓单、排名仍保留明确的发布规则待核验原因，详见QUALITY_VERIFICATION.md。

HTTP：`POST /api/v1/freshness/query`，参数 `sources`（可多选）、`search`（维护名称/代码/周期）、`limit=1..200`、`offset`；返回 `rows/total/next_offset/evaluated_at`。健康接口的 `scheduled_freshness` 返回同口径首页，SDK使用 `client.freshness(...)`。每页在同一只读数据库快照内计算，无需QMT/Tushare在线，不写任务、不自动补数，不修改旧任务质量结论。

每条记录包含维护范围ID、来源、对象、周期、维护时间、截止日、目标日、最新数据日、最近写入、状态、原因代码和建议动作。维护时间只是用户设置的更新目标，不冒充官方发布时间保证。当前界面支持筛选、跨页和记录详情；查看状态不会触发上游请求。
