# Web 控制台

## 页面与入口

数据查询包括证券目录、实时行情、历史行情、指数成分和行业概念；期货资料按交易日历、主力连续映射、仓单、排名、结算参数和交易周报分别进入。采集管理分为数据集、采集执行、任务记录、导出记录和自动维护。质量运维分为运行概览、数据质量、任务日志、服务日志。系统设置分开账号、QMT、数据库和访问配置。

旧 `#market`、`#futures`、`#operations`、`#settings` 分别进入证券目录、交易日历、运行概览和账号页。任务详情使用 `#task/<任务ID>`。手机通过菜单展开导航。

顶部“全局数据来源”在所有页面可见，只需切换一次。目录、行情、数据集、任务、维护、新鲜度、统计与服务日志统一使用该来源，页面跳转不会改换来源，刷新后保留浏览器中的选择。当前来源不支持的页面显示说明，不自动改用其他来源。账号、数据库及终端部署属于系统管理，仍可直接访问；已经创建的任务保持原来的固定来源。

运维导航在请求进行中仍可点击；服务日志单独读取，不等待数据质量统计。数据集操作列使用带名称提示的图标按钮，手机按两列排列。

## 查询与分析

历史行情查询后，范围汇总显示为分页表格；先看分组记录数和价格/量额摘要，再从某一组进入K线。搜索或翻页只改变汇总表，图表窗口保持独立。主力映射和结算参数使用合约名称展示，代码放在名称下方作为识别信息。

仓单日报和成交持仓排名可展开“明细筛选”，读取所选品种、日期的仓库/单位或会员选项，支持多选。点击查询应用后，图表、统计和导出遵循相同条件；改变范围后可刷新选项，暂时没有记录的已选条件会保留并注明。

这些条件用于已入库资料查询。点击“采集此范围”会明确确认按交易所、品种或合约和日期采集完整资料；仓库、会员与单位不作为上游下载限制。

调整排序、每页条数只改变已查询结果；未提交条件仍会标记“尚未应用”。各期货资料页分别记忆品种、日期和展示设置，重置不会切换资料类型。表格翻页保留当前图表窗口；图表故障单独显示，不丢弃成功读取的表格。

任务详情的“分块质量”可按合约、周期、错误、执行状态及质量状态定位问题；“事件”可搜索说明并筛选时间。右上角刷新更新当前标签，返回按钮回到原列表。全局任务日志也可直接输入列表中显示的前8位任务ID。

目录、行业概念、任务、数据集、维护、质量和事件列表的翻页与全选，使用最近成功查询的条件。修改后需点击查询；失败时保留原结果并显示原因。任务可按数据集/维护名称、成员代码或任务ID搜索，再按触发方式、账号和创建日期筛选；导出页始终限定导出任务。表内长错误可展开查看。

选择数据来源与范围后点击查询。改变条件只修改草稿，当前结果和导出仍使用已应用范围；来源切换会清除不兼容结果。更多排序、每页50/100/200条、显示列和命名查询在折叠的查询设置中。查询名称与列偏好仅保存在当前浏览器，不保存账号凭据。

表格可紧凑显示数值；悬停、记录详情、复制和导出保留完整原值。NULL表示未提供。行情按来源、合约、周期分别统计全范围；K线窗口独立于表格，默认最新1000条，最多5000条，可向前后加载。图表中的数据间隔不会补零或伪造成行情。

期货资料图表最多同时展示六条序列。不同仓单单位不能合并，总计与明细不会相加。持仓排名单日视图仅比较选择的成员；周报累计值、持仓量、百分比不跨时间累计；结算费率不转换成未经确认的百分比。日历未知日期不当成休市；映射间隔不拼接成连续行情。图表原始资料最多取最新5000条，超出范围明确提示，表格与导出仍可查询完整范围。

## 编辑与执行

列表行的垃圾桶图标会把数据集、维护计划或已结束任务移入回收站；“记录范围”切换到“回收站”后可恢复。配置恢复后自动更新保持停用。行情、导出文件和追溯记录保留；活动任务及被依赖的配置会明确拒绝回收。账号删除仍检查包括回收站配置在内的引用。

Tushare数据集只要包含任意分钟周期，成员必须是具体月份合约。先选分钟周期再打开成员选择器，“全选筛选结果”会限定月份合约；若先选主力/连续合约再改周期，表单会列出不兼容成员，点击“移除不兼容成员”后再保存。没有分钟权限时仍需更换有权限账号或改用日/周/月周期，不能靠改变成员绕过权限。

目录支持跨页选择并以所选建立数据集。数据集可编辑、复制，指数和板块快照成员须显式刷新或复制为手工集合。修改不会改变已排队任务的固定成员、账号和端点。

采集执行页切换目录同步、历史回补、资料采集三种模式；资料页的“采集此范围”携带范围进入执行页。保存配置不自动发起采集。创建采集、导出和补数前分别确认范围。

自动维护默认保存为停用，可单独启用、停用、编辑、复制。改变范围需先停用并确认差异。从任务详情保存时，使用原任务固定的成员、周期、账号和端点，不读取后来改动的数据集，也不跟随默认账号。需要改用数据集当前范围时，在停用计划后显式选择数据集。

执行一次先选择日期方式：按已保存日历回读，或自定义起止日期（带快捷日期）。日历维护默认自定义日期，可在数据库还没有日历时启动首轮同步。预览不会创建任务，确认后才排队，并重新检查权限、端点和配置版本；取消不会写入。不推进自动维护游标，同一预览不重复创建任务。

修改名称、停用和复制保留原端点；账号端点变化会阻断执行。需要更新绑定时，在数据集或停用的维护编辑面板明确勾选“重新绑定所选账号的当前端点”。编辑面板的取消、关闭和Esc均检查未保存修改。配置版本变更时须重新读取，不覆盖其他窗口的修改。

## 任务与质量

任务详情分概览、分块质量、事件、关联任务。执行状态与质量状态分别呈现；部分完成不等于成功，待核验不等于失败。定向重试保留原任务证据，缺口补数继续使用预览确认流程。批量处理逐项反馈。

运行统计按任务创建日期统计当前状态，关联重试各算一个任务，不代表数据完整率。新鲜度统计覆盖当前筛选的全部启用维护对象，不限于表格当前页；新鲜度不代表连续性。数据依据不足时不显示假定的完整率。

## QMT期货日历与主力映射

若能力检测显示“有限可用”，表示当前大QMT没有独立交易所日历，但能从合约日线读取已观察交易日。采集后可在日历查看这些日期，其他日期显示“未知”；任务“部分完成”表示日历完整性仍待确认，并非代码解析失败。当前映射可独立使用，历史映射空响应不代表当前映射不可用。

全局来源选择QMT后，进入“交易日历”选择交易所和日期查询已入库数据；“检测资料能力”为只读小样本检测，“采集此范围”进入确认后创建同步任务。月历缺少依据的日期显示未知，表格显示日历依据和采集时间，可切换月历、列表或同时查看。

“主力连续映射”默认当前映射：选择QMT目录中的主力连续合约，查询最新保存快照，或采集当前关系。当前模式没有历史日期筛选；终端交易日可不同于采集日，缺失交易日不填今天。切换“历史逐日映射”后按日期查询/采集，当前快照不会出现在历史曲线中。对应月份合约可直接进入历史行情页。

QMT资料无需Tushare账号。无接口、权限不足、空响应和连接失败分别显示；旧PFOR_MARKET需要在退出QMT后更新。未获得历史能力时当前映射仍可独立使用。查询、统计和CSV/Parquet导出始终读取数据库，QMT离线也能使用。

可从采集范围保存维护计划，默认停用和17:00；启用后日历及当前快照按自然日维护，历史映射依据已确认交易日历维护。停机错过的当前快照不倒填，恢复后仅采最新关系。

## 接口与兼容

新增 POST `/api/v1/history/summary`、`/history/chart`、`/futures/summary`、`/operations/summary`，由同一筛选逻辑读取PostgreSQL，数据库查询不要求QMT或Tushare在线。统计返回完整总数、实际范围、口径、评估时间及快照标识；图表额外返回前后窗口与截断信息。快照变化明确要求重新查询。

历史接口通过可选sort/direction/include_total启用稳定排序和完整总数；DataClient提供history_summary、history_chart、futures_summary、operations_summary、query_datasets、query_maintenance和版本化配置更新方法。流式资料导出使用既有事务快照，不按每个分块重复统计整个导出范围。

POST `/datasets/query`、`/maintenance/query` 提供配置分页；POST `/console/datasets/<id>` 要求revision；POST `/console/maintenance` 创建停用计划，`/<id>` 编辑，`/<id>/scope-preview` 比较范围，`/<id>/preview` 生成五分钟有效执行预览，`/<id>/run` 确认执行。

旧接口默认行为保留；新控制台使用版本字段防止并发覆盖。schema9仅增加配置版本、触发器和查询索引，不改写原行情字段。服务地址和端口保存后需要重启生效。
