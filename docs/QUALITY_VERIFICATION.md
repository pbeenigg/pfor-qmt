# 质量核验与剩余验收

## 只读重新核验

在下载任务详情点击「只读重新核验」，会创建独立的verify任务。任务复用导出队列，读取原任务相同来源、对象、周期和日期范围的数据库数据，不请求QMT/Tushare、不需要账号在线、不改写行情或原任务。支持排队、取消、重启续跑及失败重试。

核验结论与采集结果分别保留。核验通过不代表原采集请求当时成功，不补造上游响应；没有日历或分钟依据时仍保留明确的待核验原因。大范围按原分块读取，每页5000条，分块结论与检查点同事务保存。

HTTP：`POST /api/v1/jobs/{id}/verify`，返回新任务ID；重复点击返回同一个活动核验。SDK：`client.verify(job_id)`。不接受活动任务、目录或导出任务。新任务payload.verification_of记录原任务ID，不混入补数子任务链。

「分块质量」的详情包含请求范围、错误码、规则版本和异常区间；规则版本为coverage-v2。核验只返回当前数据库快照的结论，未写入行情的坏响应仍需查看原任务异常样本。

## 核验缺口补数

核验任务详情提供「预览缺口补数」，分块详情也可只选一个分块。预览列出固定来源、原采集账号和端点，以及准确的对象、周期、起止日期；取消不创建任务。确认后创建普通download任务，继续复用原采集、校验、入库、取消、恢复和导出链路。

只接受有明确日期的BARS_MISSING、CALENDAR_MISSING、PERIOD_STALE和已结束PERIOD_OPEN。同一分块的相邻日期合并，始终限制在原请求范围；分钟时段、未知夜盘、发布规则不明、坏响应等问题不会自动转成下载。若怀疑停牌或无成交，应先核对预览再提交。周/月未结束时不补；日历可以补原请求中的未来日期。

预览不需要来源在线；提交Tushare补数要求原账号可用且端点一致，默认账号改变不影响绑定。提交携带preview_key，范围变化会要求重新预览；并发或重复确认返回同一活动任务。已校验通过的补数范围及其成功重试不重复创建。补数不加入自动维护、不修改原采集或核验结论；完成后通过「只读重新核验」验证结果。

详情中的「关联任务」可跳转原任务、关联重试、核验和缺口补数，支持分页。HTTP新增POST /jobs/{id}/repair-preview、POST /jobs/{id}/repair、GET /jobs/{id}/links；SDK为preview_repair、repair和job_links。预览最多展示100个区间，total与truncated明确说明是否还有更多；确认仍处理完整选定范围，超过100000个区间直接拒绝。

```python
preview = client.preview_repair(verification_id, unit_indices=[0])
job = client.repair(verification_id, preview['preview_key'], preview['unit_indices'])
links = client.job_links(verification_id)
```

## 判定规则

- 日线：复查OHLC、数量、精度与已保存日历；缺日历不推断休市，空字段不补零，合约存续期外不要求补数。
- 周/月线：按上游周五/月末标签与计算截至日期处理。相同周期选择最新修订，同截至日冲突拒绝；周期结束日完整经过、周期日历齐全且截至日达到最后开市日后，才确认周期覆盖。周五或月末休市不导致永久等待；缺日历保留待核验。
- 分钟：保留原始时间和明确提供的交易日，不猜测夜盘归属。根据已保存时段描述列出较长记录间隔，最多展示20个样本并返回总数；这些是待核对的间隔，不等同于缺失分钟，不能证明完整交易时段。空表单独说明未取得记录。
- 日历：后台获取Tushare日历保存开市、休市和前一交易日。核验检查请求窗口的自然日覆盖。
- 映射：按对应来源开市日查验，不跨市场借日历。
- 仓单、排名：检查自身维度和非负存量；变化量可为负，NULL保留。逐品种适用条件和准确发布时间没有足够依据，空响应保持待核验，不强行标为未发布或缺失。
- 目录：新鲜度达到目标需有该维护范围的完整任务及全部分块校验提交证据，旧任务成功状态不能替代新证据。

自动补数查看整个关联任务链，已修复部分不重复，未结束周期及无权限接口不阻止其他明确可补范围。仍仅处理启用维护的范围，最多三轮；认证、配置与配额错误不自动重试。核验任务不自动触发上游补数。

关联链最近一次补数被取消后，不自动重建该次补数；用户手动继续后才重新评估。取消单次任务不等同于停用以后日期的维护计划。

## 运行故障

数据库断开时运行面板仍显示数据库故障、本地可用空间及工作进程日志；无法读取的任务信息明确标注暂不可读取。`GET /api/v1/runtime/events`与`client.runtime_events()`只读取本项目固定日志文件，每文件末尾64KiB、最多100条，截断会标明，凭据脱敏。恢复数据库后刷新可重新查询持久化事件。

## 依据与边界

2026-09-18核对Tushare官方[周/月线](https://tushare.pro/document/2?doc_id=337)、[分钟](https://tushare.pro/document/2?doc_id=313)、[日历](https://tushare.pro/document/2?doc_id=467)、[仓单](https://tushare.pro/document/2?doc_id=140)、[排名](https://tushare.pro/document/2?doc_id=139)。分钟文档未提供交易日字段、完整历史时段规则或无成交补条保证；仓单与排名文档未承诺具体发布时间。合约时段描述存在省略盘中休市的情况，不能机械解析后声称全量连续性通过。
