# 全链路稳健性实施记录

## 范围与决策

沿用统一证券目录、PostgreSQL schema、任务队列和原生工作台，不引入第二套数据系统。用户确认自动维护为主、坏合约隔离、批次级追溯；维护支持所有现有资料，范围需显式保存。仅站内告警与日志，事件保留90天、异常样本30天，不保存全部原始响应。

## 实施与验收清单

- [x] 执行状态与质量状态分离，稳定错误码、原因和下一步动作。
- [x] OHLC区间、重复时间冲突、非有限值和负成交量校验；保留NULL、Decimal和夜盘时间语义。
- [x] 分块结果与入库原子提交；异常隔离、重启恢复、取消和关联定向重试。
- [x] 持久化任务事件、分页查询、脱敏样本和到期清理；工作台日志与健康面板。
- [x] 目录、日历、K线、映射、仓单和排名的显式维护范围；有限补数、调度去重。
- [x] HTTP、SDK、页面和导出一致；旧任务保留，迁移可重复执行。
- [x] 隔离数据库与故障注入回归，桌面/移动浏览器验证，部署结果与未验证项分别记录。

## 状态口径

执行状态：queued、running、retrying、succeeded、partial、failed、blocked、cancelled。partial表示部分完成；blocked表示前置条件不足。迁移将旧completed转换为succeeded，旧API筛选completed仍接受并映射。

数据质量：verified、pending_verification、not_published、not_applicable、missing、rejected、stale。verified只表示已执行校验通过，不承诺未经验证的分钟连续性。空响应无发布规则证据时保持待核验，不能猜测为未发布或不适用。未结束的周/月线保存上游当前值，单独标记等待周期结束。

重试生成关联子任务；保留原任务及已入库数据。仅重试失败、缺失和明确可补范围，不能通过反复下载消除未知夜盘归属或未知交易时段。取消只停止后续处理，不能撤销上游请求。

## 验证边界与后续项

本轮不补造旧任务事件；新事件从升级后的任务开始产生。原行情及15张业务表原字段哈希一致，旧失败任务未自动重跑。

分钟逐时段连续性、夜盘归属、仓单/排名逐品种发布规则仍缺少已核验依据，保持pending_verification。stale已定义为质量词汇，但尚未按资料发布时效自动计算，当前健康接口仅报告最近行情/写入时间和维护状态；需要明确各资料时效规则后补充，不按自然日硬判过期。数据库容器卷余量为未验证，仅监测本地运行目录磁盘。备份已检查归档目录，尚未做独立恢复演练。

新增维护和补数策略已用隔离数据库、模拟数据源验证；实际QMT历史源、真实分钟权限与跨交易日长跑未在本轮验证。无需等待这些外部能力即可使用日志、定向重试和数据库查询导出。
