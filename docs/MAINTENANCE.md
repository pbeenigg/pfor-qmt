# 自动维护操作与恢复

## 启用与编辑

数据集自动更新与从任务保存的维护计划共用调度流程。同一数据集只能启用一种方式；新建计划、重新启用和并发操作均检查冲突。相同范围不能同时启用两个维护计划。

在「运行与日志 → 自动维护范围」点击编辑，可修改名称、每日时间和回读交易日数。修改会保留当前启停状态、已选对象、来源、账号、端点及已排队任务。取消编辑不会写入。范围或账号需要变化时，从新的原始采集任务保存新范围。

重复启用已启用的数据集不会重置起始日期；从停用变为启用仍按既有规则从启用当日跟踪。维护计划重新启用保留原有检查点，继续补齐未排队日期。停用阻止后续新任务，不取消已排队任务，也不能撤回已发出的日历请求。

## 多交易所与检查点

下载和资料维护按交易所分组，分别计算最后排队日期与回读窗口；一处日历故障不阻止其他已选交易所。休市日期只依据对应来源日历，不借用其他市场，不推断周末必然休市。

每个范围、交易所和结束日期只有一个schedule_key。兼容旧任务的全范围日期键：根据旧任务实际成员或资料选择继承该市场检查点，不批量重写旧任务。恢复故障市场时只补它未排队的范围，已经排队的其他市场不重复。仍保持同一来源串行采集。

提交新任务前会锁定并重新读取范围；日历读取期间发生停用或编辑时，不按旧设置排队。停止服务时同样停止后续排队；重启恢复原任务检查点。

## 错误与恢复

日历权限、认证、不支持和配额错误在当前进程记住阻断原因，不每分钟重复访问同一账号和市场。更换Token、端点、请求频率，重新检测账号权限，或重新启用范围后允许再检查；服务重启也会重新检测。没有轮换账号或自动切源。

日历在线请求失败时可使用已保存真实日期，但仍保留故障说明；资料不足以组成回读窗口时不创建任务。网络恢复、账号修正及日历补齐后，按各市场检查点恢复。

创建、编辑、启停、排队、调度阻塞与恢复均进入事件日志。相同阻塞在同一进程中只记录状态变化，避免每分钟重复刷屏；全局事件保留实际QMT/Tushare来源，可按来源筛选。

SDK：`client.update_maintenance(plan_id, name="收盘更新", schedule_time="19:30", lookback_days=5)`；原`client.set_maintenance(plan_id, False)`继续支持。HTTP为`POST /api/v1/maintenance/{id}`，仅接受上述设置及enabled，不允许从此接口改写固定范围。
